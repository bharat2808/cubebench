# Security and deployment boundaries

The default listener binds loopback. Hostname allowlisting protects against DNS rebinding. Origin is checked exactly; the default accepts the request's own origin and configured public URL. Override comma-separated `CUBEBENCH_ALLOWED_HOSTS` (hostnames) and `CUBEBENCH_ALLOWED_ORIGINS` (exact origins) for a reviewed deployment. Browser mutations require a matching same origin and `X-CubeBench: 1`. The JSON body limit is 128 KiB. Per-address rate and concurrent request limits apply, including SSE connections. No full bearer tokens are logged or copied into SDK request context.

Local access credentials are random, hashed in SQLite, expire, and contain an explicit community/runner/admin role. Anonymous browser sessions use scoped community credentials in HttpOnly, SameSite=Strict cookies. Private resources require the owner; absence of ownership is not a public existence oracle. Operator identities and trusted runners are distinct from claimed provider/model metadata. Human history belongs to its anonymous session and never enters benchmark ranking.

For hosted OAuth, set `CUBEBENCH_OAUTH_ISSUER`, `CUBEBENCH_OAUTH_JWKS`, and `CUBEBENCH_PUBLIC_URL`. Use an external authorization server: this application is only a resource server. JOSE validates signature, issuer, expiry, subject, and audience `${CUBEBENCH_PUBLIC_URL}/mcp`. OAuth tokens must carry `cubebench:compete`. Runner authority additionally requires `cubebench:run-ranked` and an explicit subject in `CUBEBENCH_TRUSTED_RUNNERS`; other valid scoped subjects remain community. Successfully authenticated OAuth identities are persisted without credentials. Protected-resource metadata is exposed at `/.well-known/oauth-protected-resource/mcp` (and root alias), and 401 responses advertise its URL in WWW-Authenticate. Set NODE_ENV=production, which requires an HTTPS public URL and Secure browser cookies. Hosted OAuth issuer and JWKS URLs must also use HTTPS. Production responses send HSTS and a same-origin Content Security Policy; credential and API responses use Cache-Control: no-store. Terminate TLS at a trusted reverse proxy and configure the external Host allowlist explicitly; do not expose the loopback origin directly.

Keep the database and Ed25519 private key on durable, access-controlled storage. Restrict the entire working data directory to the service account, back it up securely, and keep signing keys stable across restarts. The process owns authoritative monotonic clocks. Only one benchmark authority may write/run matches against a database. Restart recovery ends unfinished attempts as disconnected; official durations are never reconstructed from wall time.

Public match/run/event routes apply round visibility gates before serialization. Seeds and signed result export require completed matches, and owned private matches stay private. SSE reads committed database events; it never publishes uncommitted transitions. Access tokens and participant/run tokens are separate credentials. Do not put any tokens or provider credentials into prompts, URLs, logs, screenshots or shared exports.

Known boundaries: no bundled OAuth issuer, no horizontal timing worker coordination, no PostgreSQL implementation, no general NxN reachability proof for arbitrary hand-edited state, and no claim that random legal-move scrambles are uniform random states. Production operators should configure network-level quotas and audit retention appropriate to their deployment.
